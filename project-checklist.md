# Project Publication Checklist

## Before Development

- [ ] The business question is clearly defined.
- [ ] The dataset source and license are documented.
- [ ] No confidential or personally identifiable information is included.
- [ ] The project folder uses a descriptive kebab-case name.

## During Analysis

- [ ] Data types, missing values, duplicates, and outliers are reviewed.
- [ ] Cleaning and transformation decisions are documented.
- [ ] Charts have titles, labels, units, and readable colors.
- [ ] Code is organized and avoids unnecessary repetition.

## Before Publication

- [ ] The project README follows the repository template.
- [ ] Key findings are supported by metrics or visuals.
- [ ] Business recommendations are separated from observations.
- [ ] Limitations and assumptions are documented.
- [ ] The analysis can be reproduced from the documented steps.
- [ ] Temporary files, credentials, and large raw datasets are excluded.
- [ ] Links and images have been checked.
